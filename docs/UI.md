# 画面デザイン・遷移・ボタン割り当て（モック）

対象: 128 × 128 モノクロ OLED（1bpp）

> モック中の絵文字は**見た目の説明用**。実機は 1bpp なので、実際は自前のビットマップアイコンになる。

---

## 1. 入力

`services/bao1x-hal-service/src/servers/keyboard.rs` の `map_keypress()` が、
物理入力を以下の文字にマップしている。

| キーコード | 物理入力 | 位置 |
|---|---|---|
| `←` | `KeyPress::Left` | **左ボタン** |
| `🔥` | `KeyPress::Center` | **中央ボタン** |
| `→` | `KeyPress::Right` | **右ボタン** |
| `↑` `↓` | `KeyPress::Up` / `Down` | ジョグ（別位置） |
| `∴` | `KeyPress::Select` | ジョグ押し込み（別位置） |

`🔥` は "Fire" の意。ソースのコメントによれば、キャリッジリターン（`\r`）が
シェルの行末に予約されているため、中央キーには専用の文字が割り当てられている。

`dc34-vault` でも `←` `→` `🔥` の3つを一組として扱う判定があり（`ux.rs:286`）、
この3つが横並びの3ボタンであることを裏付けている。

### 割り当て

**上下キー（`↑` `↓`）とジョグ押し込み（`∴`）は使わない。** 3ボタンで完結させる。

| ボタン | キーコード | 役割 |
|---|---|---|
| **左** | `←` | **選択** — カーソルを1つ進める（右端で左端へ循環） |
| **中央** | `🔥` | **決定** — 選択中の項目を実行 |
| **右** | `→` | **キャンセル** — 戻る / やめる |

> **補足**: 左ボタンでカーソルが右に進むので、物理配置と移動方向は逆になる。
> 3 ボタンで選択・決定・キャンセルを賄うには、選択ボタンを一方向の送りにするのが素直。
> 違和感が強い場合は、
> 「`←` `→` で双方向移動、キャンセルは中央長押し」に変更する余地がある。
> ただし長押し判定が必要になるため、まずは循環方式で試す。

## 2. 画面レイアウト

縦 128px を 3 段に分ける。

```
        0 ┌──────────────────────────────┐
          │  ステータスバー (16px)        │   世代・日数・ごきげん・空腹
       16 ├──────────────────────────────┤
          │                              │
          │                              │
          │   キャラクター領域 (96px)     │   キャラ・うんち・アニメーション
          │                              │
          │                              │
      112 ├──────────────────────────────┤
          │  メニューバー (16px)          │   アイコン6個、選択中は反転
      128 └──────────────────────────────┘
```

96 × 96 のキャラ領域は 9216 px。ドット絵に十分な余裕があり、
表情や動きで状態を表現できる。

## 3. 各画面

### 3.1 メイン画面（アイドル）

常態。キャラが歩き回り、うんちが溜まる。

```
┌──────────────────────────────┐
│ G3  D4      ♥♥♡♡   ▮▮▮▯      │
├──────────────────────────────┤
│                              │
│           ( ˘ ω ˘ )          │
│            /|   |\           │
│           ~        💩        │
│                              │
├──────────────────────────────┤
│ [🍚] 🎮  🧹  💊  📖  ⚙       │
└──────────────────────────────┘
```

- `G3` = 第3世代、`D4` = ゲーム内4日目
- `♥` = ごきげん（4段階）、`▮` = 満腹度（4段階）
- 選択中のアイコンは白黒反転

| ボタン | 動作 |
|---|---|
| `←` 選択 | カーソルを1つ右へ（循環） |
| `🔥` 決定 | 選択中のメニューを実行 |
| `→` キャンセル | カーソル選択を解除（何も選んでいない状態に戻る） |

### 3.2 メニュー項目

| アイコン | 名前 | 動作 |
|---|---|---|
| 🍚 | ごはん | サブメニュー（ごはん / おやつ）へ |
| 🎮 | あそぶ | ミニゲームへ |
| 🧹 | そうじ | うんちを消す。即実行 |
| 💊 | くすり | 病気を治す。病気でなければ「げんき！」表示 |
| 📖 | しつけ | 呼び出し中なら叱る。そうでなければ無反応（＝ミス扱いにしない） |
| ⚙ | メニュー | サブメニュー（ステータス / セーブ / おわる）へ |

### 3.3 ごはんサブメニュー

```
┌──────────────────────────────┐
│ G3  D4      ♥♥♡♡   ▮▮▮▯      │
├──────────────────────────────┤
│                              │
│      ┌────────────────┐      │
│      │ ▶ ごはん        │      │
│      │   おやつ        │      │
│      └────────────────┘      │
│                              │
├──────────────────────────────┤
│  ← えらぶ  🔥 きめる  → もどる │
└──────────────────────────────┘
```

- ごはん = 満腹度 +1、体重 +1
- おやつ = ごきげん +1、体重 +2

| ボタン | 動作 |
|---|---|
| `←` 選択 | 項目を1つ下へ（循環） |
| `🔥` 決定 | 実行 → アニメーション → メイン画面 |
| `→` キャンセル | メイン画面へ戻る |

### 3.4 ⚙ サブメニュー

「メインメニューに戻る」と「セーブ」はここに置く。

```
┌──────────────────────────────┐
│ G3  D4      ♥♥♡♡   ▮▮▮▯      │
├──────────────────────────────┤
│      ┌────────────────┐      │
│      │ ▶ ステータス    │      │
│      │   セーブ        │      │
│      │   おわる        │      │
│      └────────────────┘      │
│                              │
├──────────────────────────────┤
│  ← えらぶ  🔥 きめる  → もどる │
└──────────────────────────────┘
```

| 項目 | 動作 |
|---|---|
| ステータス | ステータス画面へ |
| セーブ | 即セーブし、「セーブしました」を数秒表示してメイン画面へ |
| おわる | **セーブしてから** Xous のメインメニューへ復帰 |

**設計意図**: セーブは自動（状態変化時＋ディープスリープ突入前）で行われるため、
本来この項目は不要。しかし USB を抜く運用なので、
「抜く前に自分で保存できる」という安心感のために明示的に置く。
`おわる` も必ずセーブを挟むので、実質どちらを選んでも安全に終われる。

> **代替案**: 公式アプリ（`dc34-vault`）では `∴`（ジョグ押し込み）が
> 「メニューを開く」システム的な役割を持っている（`main.rs:395`）。
> 3ボタン縛りを緩めてよいなら、`∴` に「おわる」を割り当てる方が
> 他アプリとの一貫性は高い。今回はメニュー項目として実装する。

### 3.5 ミニゲーム（左右あて）

キャラがどちらを向くかを当てる。

```
┌──────────────────────────────┐
│         あそぶ  2/5          │
├──────────────────────────────┤
│                              │
│         ( ˘ ω ˘ )            │
│                              │
│      ▶ ひだり    みぎ        │
│                              │
├──────────────────────────────┤
│  ← えらぶ  🔥 きめる  → やめる │
└──────────────────────────────┘
```

- 5 回勝負。3 回以上当てるとごきげん +2、体重 -1
- 負け越したらごきげん +1、体重 -1

| ボタン | 動作 |
|---|---|
| `←` 選択 | ひだり / みぎ を切り替え |
| `🔥` 決定 | answer を確定 |
| `→` キャンセル | 中断してメイン画面へ |

### 3.7 睡眠中

ゲーム内 0〜4 時（累計稼働 20 分）。

```
┌──────────────────────────────┐
│ G3  D4                       │
├──────────────────────────────┤
│                              │
│              z z             │
│         ( ─ ω ─ )            │
│                              │
│                              │
├──────────────────────────────┤
│         おやすみ…            │

```

- **操作を受け付けない**（メニューバーも消す）
- 「就寝中に消灯しないとケアミス」という判定は**採用しない**。

  プレイヤーが消灯できたかどうかを公平に判定できない

## 5. ボタン割り当て一覧

| 画面 | `←` 選択 | `🔥` 決定 | `→` キャンセル |
|---|---|---|---|
| メイン | カーソル送り | 実行 | 選択解除 |
| ごはんメニュー | 項目送り | 実行 | メインへ戻る |
| ⚙ メニュー | 項目送り | 実行 | メインへ戻る |
| ミニゲーム | 左右切り替え | 確定 | 中断 |
| ステータス | — | 戻る | 戻る |
| 睡眠中 | — | — | — |
| 進化 / 寿命 / 終了 | — | つづける | — |
| 卵 | — | — | — |

**原則**: `🔥` は常に「進む・決定」、`→` は常に「戻る・やめる」、`←` は常に「選ぶ」。
`↑` `↓` `∴` は未使用。

## 6. 実装メモ

- ステータスバーとメニューバーは共通コンポーネントにして、全画面で使い回す
- キャラの表情は「通常 / 困り / 喜び / 病気 / 睡眠 / 死亡」の 6 種類あれば足りる。
  1 枚 96×96 の 1bpp ビットマップで 1152 バイト、6 枚で約 7 KB
- 画面の再描画は状態変化時のみ。`dc34-vault` の `redraw()` が
  「前回のモードと違うときだけ描く」構造になっているので、それに倣う
- ミニゲームの乱数は TRNG が使える（`bao1x-emu` に hosted 用シムもある）
- `↑` `↓` `∴` は受け取っても無視する。
  ただし `∴` は公式アプリでメニューキーとして使われているため、
  将来的に「おわる」を割り当てる余地は残しておく
